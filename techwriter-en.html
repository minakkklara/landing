Case Studies

Automating release notes

Problem
Release notes were compiled manually, so some key features got lost in the flow of shipped updates and users didn't learn about important product changes.
Solution
By configuring components in Jira, the release notes export was automated and all shipped features were split into blocks, which made working with update information much simpler.
Result
Cut the time spent compiling release notes from 2 hours to 2 minutes — a 60x reduction. This freed up the technical writer's time and improved the quality of feature write-ups before publication.

Payments guide development

Problem
Information about payment processing in mobile apps was scattered across different sections of the documentation. Developers had no unified picture of payment integration, creating paid products and subscriptions, or connecting the API.
Solution
The solution was creating a single page with a payment usage scenario: from enabling monetization in mobile apps to configuring the API and test payments.
Result
This improved the developer experience and reduced the number of support requests.

Migrating to Docusaurus

Problem
At the start of the RuStore project, documentation was maintained in a standard CMS, which severely limited what technical writers could do. In particular, inserting code samples was a problem — code examples didn't always look good in the layout, and developers found it hard to apply them in practice.
Solution
To fix this, the entire documentation was migrated to Docusaurus, enabling instructions to be written using Markdown.
Result
This not only improved the look of the text and code sample blocks, but also made it possible to involve other RuStore teams in creating documentation.
